# Spec 0002 — Revenu de solidarité active (RSA)

**Status:** Draft · **Priority:** P1 (first roadmap benefit) ·
**Depends on:** Spec 0001 (salary-input semantics) — do not start until merged ·
**Source:** coverage.md "largest gap", PENDING_NEXT_STEPS #1, PROPOSED #1 ·
**Est. effort:** 3–4 days

---

## 1. Goal

Model the **revenu de solidarité active** — the differential minimum-income
top-up — as the first means-tested benefit, establishing the resource-base and
forfait-logement machinery that prime d'activité and APL will reuse.

RSA is the highest-value missing item (coverage.md "the largest gap") and
dominates low-income household budgets, exactly the distributional question a
microsimulation exists to answer.

## 2. Why it is gated on Spec 0001

RSA's `base_ressources` is built from **net/declared** income concepts. On the
current dual-convention input it cannot be computed honestly (see Spec 0001 §1).
Once `salaire_declare` and the cotisations layer exist, the resource base is
well-defined. **Do not implement RSA before 0001 lands.**

## 3. Statute scope (CASF art. L262-1 et seq., R262-*)

Model the **socle** (base RSA), 2024 parameters:

- **Montant forfaitaire** by household composition (CASF art. R262-1):
  1 personne, majoration couple, majoration par enfant, and the
  parent-isolé majoration (RSA majoré). Values indexed 1 April.
- **Base ressources** — average monthly resources over the 3 months preceding
  the demand (art. R262-3). MVP: use the modelled annual income ÷ 12 as the
  monthly proxy (the same N-vs-N-2 style simplification already disclosed for
  AF), explicitly flagged.
- **Forfait logement** (art. R262-9) — a flat deduction from the montant
  forfaitaire when the household is housed free / owns / receives a housing
  aid, scaled by household size (1/2/3+ persons).
- **RSA = max(montant_forfaitaire − forfait_logement − base_ressources, 0)**.

### Out of scope (disclose in docstring + modelled_policies.yaml)

- Prime d'activité (separate benefit — its own spec).
- RSA jeune, RSA majoré duration limits, contrat d'engagement / sanctions.
- Neutralisation / abattement on activity income during the first 3 months
  (art. R262-7) — MVP applies the base ressources flat.
- Cristallisation, cumul intéressement.

## 4. Design

New tree under `gov/cnaf/prestations/rsa/` (mirrors AF/ASF layout):

| Kind | Path |
|---|---|
| params | `parameters/gov/cnaf/prestations/rsa/montant_forfaitaire/base.yaml` |
| params | `.../montant_forfaitaire/majoration_couple.yaml` |
| params | `.../montant_forfaitaire/majoration_enfant.yaml` |
| params | `.../montant_forfaitaire/majoration_isole.yaml` |
| params | `.../forfait_logement/{une,deux,trois_plus}_personne.yaml` |
| variable | `variables/gov/cnaf/prestations/rsa/rsa_base_ressources.py` (Famille, MONTH) |
| variable | `variables/gov/cnaf/prestations/rsa/rsa_montant_forfaitaire.py` (Famille, MONTH) |
| variable | `variables/gov/cnaf/prestations/rsa/rsa_forfait_logement.py` (Famille, MONTH) |
| variable | `variables/gov/cnaf/prestations/rsa/rsa.py` (Famille, MONTH) |

Entity: **Famille** (RSA is a foyer-social benefit), definition_period MONTH,
annualised via ADD in `revenu_disponible` like AF/ASF.

`rsa_base_ressources` aggregates, per famille member and month:
`salaire_declare/12`, `pensions_alimentaires_percues/12`, AF, ASF (family
benefits count in the RSA base per art. R262-6, with named exceptions), minus
nothing else in the MVP. Every inclusion/exclusion listed in the docstring
against its article.

### `revenu_disponible` integration

Add `+ rsa` (annualised, famille-distributed) to the identity. Guard the
ordering: RSA sits *after* AF/ASF because those feed its base ressources.

## 5. Tests & acceptance

1. **Parameter transcription** — montant forfaitaire single = published 2024
   value (≈ 635.71 €/mo from 2024-04); couple and per-child majorations
   reproduce the published couple / 2-child amounts. Unit test per composition.
2. **Differential behaviour** — a household with resources above the forfait
   gets 0; at half the forfait gets half; at 0 resources gets the full forfait
   minus forfait logement. Table test.
3. **Oracle** — capture 3–4 households from the CAF RSA estimateur (or
   openfisca-france, the established second oracle here) into
   `oracle_values.yaml` with tolerance; skip-until-captured like the rest.
4. **Integration** — a low-income famille's `revenu_disponible` rises by exactly
   the annualised RSA; a high-income one is unchanged.
5. `make test` + pytest green; changelog fragment; coverage.md + modelled_policies
   updated (RSA moves from ❌ to ✅ with its simplifications listed).

## 6. Risks

- **Base-ressources perimeter** is the subtle part (which benefits count, the
  abattements). Get the perimeter list reviewed against openfisca-france's
  `rsa_base_ressources` before finalising; the statute-review CI gate
  (Spec 0003) is designed to catch exactly this.
- **Monthly vs annual** proxy will diverge for households with intra-year income
  changes — same class of simplification as AF, disclose identically.
